# LLM Rules — 행동 지침과 새 규칙 추가 절차

이 문서는 LLM이 워크플로우 진행 중 **반드시** 지켜야 할 행동 원칙과,
docs/ 에 없는 결정이 필요할 때의 처리 절차를 정의합니다.

## 1. 핵심 원칙 4가지

1. **임의 해석 금지** — 정보가 부족하면 추측하지 말고 묻습니다.
2. **TailwindCSS 우선** — custom CSS는 Tailwind로 표현 불가능할 때만 사용합니다.
3. **추천 답안 필수** — 모든 질문은 추천안과 근거를 동반합니다.
4. **CONVENTIONS 우선** — 네이밍/구조/스타일은 `architecture/`, `style/` 의 규칙을 따르며, 새 패턴이 필요하면 사용자 확인 후 문서에 추가합니다.

## 2. 질문 작성 규약

LLM이 사용자에게 던지는 모든 질문은 다음 형식을 따릅니다.

```
Q. [질문 내용]
- 추천: [추천안] ([근거 — 보통 docs 내의 어떤 규칙과 부합하는지])
- 다른 옵션:
  · [옵션 A] ([트레이드오프])
  · [옵션 B] ([트레이드오프])
```

추가 규칙:
- **묶어서 질문** — 여러 결정이 필요하면 한 번에 정리해 묻습니다.
- **단계마다 한 개씩 묻지 말 것** — 사용자 흐름이 끊깁니다.
- **추천 없이 묻지 말 것** — "어떻게 할까요?"만 던지는 질문은 금지.

## 3. 임의 해석 금지의 구체적 의미

다음의 경우 LLM은 결정을 내리지 않고 사용자에게 묻습니다.

- 새 variant 이름을 정해야 할 때
- 새 size 토큰(`xl` 등)을 추가해야 할 때
- props 네이밍이 docs 의 컨벤션과 다를 가능성이 있을 때
- 접근성 요구사항이 유저스토리만으로 결정 불가능할 때
- shadcn 베이스 코드와 본 디자인 시스템 컨벤션이 충돌할 때

## 4. 새 규칙 추가 절차

`architecture/`, `style/` 등에 없는 패턴이 필요할 때:

1. LLM은 임의로 결정하지 않습니다.
2. 사용자에게 **추천안 + 다른 옵션 + 근거**를 제시하고 묻습니다.
3. 결정된 사항을 **해당 폴더에 새 md 파일**로 추가합니다 (다음 번호 사용).
   - 기존 규칙을 **수정**하는 변경이면 그 파일을 직접 편집합니다.
   - **새 규칙 추가**라면 다음 번호로 새 md 파일을 만들고, 그 폴더의 `index.md` 표에 한 줄 추가합니다.
4. 추가 후 다른 컴포넌트의 일관성 영향이 있는지 확인합니다 (이미 만들어진 PRD/컴포넌트와 충돌하지 않는지).
